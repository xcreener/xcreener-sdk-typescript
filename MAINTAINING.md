# Maintaining

For maintainers with publishing rights to the `@xcreener` npm scope. The
per-release steps live in [CONTRIBUTING.md](CONTRIBUTING.md#releasing); this
file covers the setup you only do once.

## One-time setup

npm differs from PyPI here: there is no *pending* publisher. A trusted
publisher can only be attached to a package that already exists on the
registry, so the very first version goes up by hand.

1. **Publish 0.1.0 manually**, from a clean checkout of the tagged commit,
   logged in as an account with 2FA enabled and write access to the scope:

   ```bash
   npm ci
   npm publish --provenance=false
   ```

   `prepublishOnly` runs the full check suite, builds, and validates the
   package before anything is uploaded. `--provenance=false` is needed only
   for this run: provenance is generated by CI, and `publishConfig` asks for
   it, so a laptop publish would otherwise fail.

2. **Attach the trusted publisher.** On npmjs.com, open the package's
   Settings, Trusted Publisher, GitHub Actions, and enter owner `xcreener`,
   repository `xcreener-sdk-typescript`, workflow `publish.yml`, environment
   `npm`. Or from the command line (npm 11.15 or later):

   ```bash
   npm trust github @xcreener/sdk --file publish.yml \
     --repo xcreener/xcreener-sdk-typescript --env npm --allow-publish
   ```

   A new trusted-publisher configuration has to complete its first publish
   within two days or it expires, so set it up when the next release is close.

3. **Create the GitHub environment** named `npm` under Settings,
   Environments. Adding yourself as a required reviewer there makes every
   publish wait for a click, which is cheap insurance for a package people
   install.

4. **Lock it down.** Once a release has gone out through the workflow, set
   the package's publishing access on npmjs.com to require 2FA and disallow
   tokens. From then on the only way to publish is the workflow.

Trusted publishing needs a GitHub-hosted runner, npm 11.5.1 or later, and
Node 22.14 or later; the workflow takes care of all three. Provenance is
attached automatically because the repository is public.

## Rehearsing

Run the Publish workflow manually from the Actions tab. A manual run does
everything a tag push does (checks, build, package validation, tarball smoke
test) and ends with `npm publish --dry-run` on the tarball. It can never
reach the registry: only a `v*` tag push publishes. npm has no separate test
registry, so this is the closest equivalent of the TestPyPI rehearsal.
